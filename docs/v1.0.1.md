# v1.0.1: class-centered study workflow

Publishing this version does not upgrade an already-running v1.0.0 installation.
Do not switch checkouts, restart the server, or change its library during recording.
Back up the library before upgrading after the recording has been saved.

## Prepare and generate

1. Create a class and open its Resources to upload PDFs, text/Markdown, or images,
   or write reusable class notes. Originals stay local. Text extraction is limited
   to 100,000 characters per material; extraction warnings remain visible.
2. Record, import, or merge a lecture. Recording finalization and media import
   transcribe locally; neither automatically calls OpenAI.
3. Assign the class, add a recording note and/or select up to 50 readable class
   resources, and save preparation. Class-wide context alone does not satisfy this gate.
4. Generate notes. The saved notes retain a snapshot of the recording note and
   selected resource names/revisions. Later material edits do not erase old notes.

Existing lecture-specific attachments remain supported. They supplement generation
but do not substitute for the explicit recording note or class-resource selection.
Changing a lecture's class clears its old resource selection. Deleting a selected
resource removes that selection and marks generated notes outdated. Busy lectures
block changes to their selected resources until processing stops.

## Relevance

Every transcript window contributes to a compact whole-lecture topic map before
segment classification. Classification distinguishes course material, class logistics,
clearly off-topic conversation, and uncertain content needing review. Relevant
examples and student questions need not appear in the provided materials.

Only course material and uncertain content feed study notes. Uncertain content is
explicitly qualified; logistics are separately filterable. No original transcript
segment or audio range is removed. The Relevance view provides timestamp seeking
and manual categories; regeneration uses these overrides. Transcript edits clear
old overrides because segment identity may have changed.

Completed transcript and relevance stages remain available if subsequent generation
fails. Content-keyed caches reuse topic maps, classifications, note chunks, and
hierarchical summaries. Force regeneration refreshes notes, not unchanged relevance
analysis. This is model-assisted sorting, not a guarantee of academic relevance;
review exclusions and important numerical details.

## Merge recordings

Choose two to twenty distinct finalized recordings from the same assigned class,
give the merged lecture a title, and order its parts. Merging creates a separate
48 kbit/s mono AAC `.m4a`; it does not delete sources or modify their notes.
Limits are six hours total, 4 GiB combined source audio/media, 1 GiB output,
30,000 transcript segments, and 2 million transcript characters.

Complete source transcripts are joined with shifted timestamps and provenance.
When any part lacks a transcript, the complete merged audio is transcribed locally.
The new lecture still requires its own preparation and explicit Generate action.
Merging is a synchronous local operation; keep its dialog open until it completes.
Selected video recordings contribute audio only; their source videos remain intact.

## Six-hour compression

New saved audio is eligible six hours after upload/final recording assembly, not
while capture is in progress. The idle local worker checks approximately every
minute and processes at most one eligible recording per check. It catches up when
the app resumes or restarts; it cannot run while the laptop or app is off. Legacy
recordings without a finalization timestamp are left untouched.

Settings controls automatic compression; an explicit class preference overrides
the workspace preference. The default is on. Active recordings, pending processing,
shared files, and videos are excluded. A compact AAC replacement must completely
decode, match the original duration, and be smaller before it becomes the saved
source. Only then are its owned original audio and redundant live WAV chunks
removed. The transcript, notes, timestamps, and source relationships remain.

Failed attempts retain the original and retry with backoff, up to five attempts.
Already-compact files are not repeatedly re-encoded. Compression is lossy and
replaces the full-quality audio; disable it before eligibility if the original
fidelity is needed. Source lectures preserved by a merge still follow their own
compression preferences and age.

## Model and privacy

New installations default to `gpt-5.4-mini` with low reasoning effort. Existing
saved or environment model selections are not silently changed. Select the new
model explicitly in Settings when upgrading. Requests use bounded context excerpts,
structured responses, and reusable caches; the relevance stage adds calls, so this
does not promise a lower total bill than v1.0.0. Usage is recorded for saved results,
not as an account-wide billing ledger. See the official
[model documentation](https://developers.openai.com/api/docs/models/gpt-5.4-mini).

Whisper and FFmpeg remain local. Only transcript and extracted supporting text go
to OpenAI, never the source recordings/images. No paid model calls are made by tests.
