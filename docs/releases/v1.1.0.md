# LecNote v1.1.0: Reading workspace

A compatible feature release bringing the approved Course Editions redesign
to the whole study workspace. Backend, API metadata, and frontend versions are
`1.1.0`. No database migration is required.

## What's new

- Read with a course rail, compact lecture index, and the selected lecture's
  player, notes, and course materials together in the Reading workspace.
- Find reusable materials in a dedicated Materials destination with course
  selection, search, safe previews, original-file access, and management.
- Keep lecture attachments distinct from reusable class resources.
- Reach recording from every page, use the Add lecture menu for uploads and
  transcript imports, and merge recordings from their course library.
- Use contextual preparation and processing controls with the existing
  unsaved-edit protection and explicit note-generation requirements.
- Navigate narrow screens with a course drawer, full-width reader, Lectures
  return link, and a course-materials disclosure.
- See the yellow-and-ink Course Editions identity, accessible keyboard controls,
  and short transitions that respect reduced-motion preferences.

## Reliability

Release review fixed a Materials-page grid issue that stretched the search field
and placed previews below the complete file list. Desktop and mobile geometry
checks now cover this state. Production smoke tests follow the new navigation
and wait for asynchronously loaded course choices.

All v1.0.2 merge/material retention and continuous final-transcription fixes
remain included. Main's no-reload frontend recovery bridge and
[recording recovery guide](../recording-recovery.md) are also retained. Navigating
between Library, Materials, and the recorder preserves live capture. Note
generation remains an explicit action; the redesign does not initiate paid calls.

## Verification and limits

The release is checked with backend and frontend unit tests, Chromium desktop
and mobile workflows, production build and lint checks, recovery-proxy tests,
and isolated real-API smoke tests including FFmpeg merges, generated-note
fixtures, attachment downloads, editing, search, and exports. See
[the verification record](../verification.md) for counts and scope.

Inference in the browser smoke tests uses deterministic fixtures. No new paid
OpenAI call, physical microphone/screen-sharing session, Safari/Firefox run,
or Windows runtime check is claimed for this release.

## Upgrade safely

1. Finish and save any active recording; keep its browser tab open until upload
   completes. Back up the entire library, not just its SQLite database.
2. Stop the old container or native server. Never run two workers against one
   library, and do not remove its data volume or bind-mounted directory.
3. Start the new image with the **same existing `/data` mount** and loopback port
   binding. Recordings, transcripts, notes, materials, settings, and downloaded
   models remain there. A new empty volume would show an empty library.

The version tag triggers verification and publication of
`ghcr.io/csingh26/lecnote:1.1.0`, `v1.1.0`, and `latest`. Check the
[release workflow](https://github.com/CSingh26/LecNote/actions/workflows/release.yml)
before pulling. Publishing a release alone does not restart an installation.
