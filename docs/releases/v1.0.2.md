# LecNote v1.0.2

## Version decision

Use a patch release: these changes repair existing workflows and improve their
presentation without requiring a database migration or breaking existing API
clients. Backend, API metadata, and frontend versions are `1.0.2`.

Work is committed on branch `v1.0.2`, with each bug fix pushed separately.
Preparing this branch does not create a release tag, publish a container image,
merge into `main`, deploy code, or restart an existing server.
The existing CI workflow is unchanged because the current GitHub login lacks
workflow-edit permission. Use its manual dispatch to check this branch; the new
merge smoke has been verified locally and is documented for repeat runs.

## Merging and recovery

Merges preserve the original recordings. The new lecture receives labeled source
context, the ordered union of selected readable same-class resources, and
independent copies of lecture attachments with source provenance. Copied files
remain downloadable even if a source lecture is later deleted. Unsupported
file types remain downloadable but cannot provide extracted text for generation.

With saved preparation and a configured OpenAI key, the merge dialog offers
**Merge and generate notes**. Its checked generation option can be turned off
for a local-only merge. The API's new `generate_notes` field defaults to `false`
for backward compatibility. Generation does not silently start after recording
or ordinary imports, and new notes are not copied from an unrelated source.

Incomplete source transcripts, including non-null interim text awaiting a final
pass, require complete local transcription of the merged audio. Manually edited
source transcripts remain authoritative. Failed queue submission rolls back the
new merge, leaving originals intact. Combined preparation above 100,000 context
characters or 50 selected resources is rejected before creating an uneditable
lecture; attachment copies reject unsafe source paths.

Existing incomplete merges are not automatically rewritten. After updating at a
convenient time, merge the original parts again to carry their materials over,
then explicitly generate notes. Alternatively, add the missing preparation to
the existing merged lecture and generate notes there. Save any active recording
and back up the library before updating an installation.

## Transcription and performance

Stop & save invalidates queued interim chunk work and assembles the original WAV.
The final pass uses continuous audio context instead of independently decoding
each uploaded part. Completed passes are cached by source content and existing
transcription settings. Cancellation or failure preserves interim text; retrying
can reuse the completed full-pass cache. Manual transcript edits are not replaced.

Older finalized live recordings without the final-pass marker are refreshed on
their next explicitly requested processing run, only if they have not been
manually edited. No background migration touches an active library. If a new
transcript changes segment IDs, timing, or text, old relevance classifications
and overrides are invalidated before analysis. Speaker-only changes preserve
relevance, and existing notes stay visible until successful regeneration.

No custom C/C++ extension is needed: [faster-whisper](https://github.com/SYSTRAN/faster-whisper)
already runs through [CTranslate2's native C++ engine](https://opennmt.net/CTranslate2/).
This update removes redundant queued work and reuses results rather than lowering
model quality settings. An in-flight interim inference can finish before the
final pass, and the final pass is still an additional local decode when interim
transcription has already completed. Large recordings require additional time;
this is not a claim that every recording now finishes faster.

A local check transcribed 14.965 seconds of synthetic speech, assembled from two
WAV parts, in 1.222 seconds with the cached base model on this laptop. The measured
cached retry took 0.001 seconds. The full sentence about force and acceleration
was retained. This small smoke check verifies the path, not long-lecture accuracy
or a general performance guarantee. No paid API request was made.

## Workspace refresh

The existing study workflow now has restrained neutral/teal surfaces, distinct
status colors, visible keyboard focus, compact controls, and verified narrow
layouts. Saved preparation can collapse on a finished lecture; unsaved changes
remain visible, and the editor state survives opening and closing the section.
Merge ordering controls and lecture headers fit at 320, 390, and 1440 pixels.

## Verification and limits

See the [verification record](../verification.md) for automated results and
reproduction commands. Coverage includes real FFmpeg merges, independent copied
attachments, resource/context provenance, queued notes through the real API,
manual-edit protection, cached retries, and review-driven regression tests.

The API/browser smoke uses deterministic inference fixtures; live OpenAI note
quality was not retested. No physical microphone, native screen-sharing picker,
multi-hour workload, Safari, Firefox, or Windows runtime was tested for this
update. Existing servers and their libraries were not modified or restarted.
